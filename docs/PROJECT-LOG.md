## Hosting notes

Cloudflare Workers: `dist/` as static assets, plus the Worker in `worker/` for `/api/*` (D-018, D-020). Pages and assets are served without running the Worker; it runs for `/api/*` and for URLs that match no file (they get the 404 page).

- **Deploy from this machine:** `npx wrangler login` once (opens the browser), then `npm run deploy`. If the login can see more than one Cloudflare account, Wrangler asks which one (or set `account_id` in `wrangler.jsonc`).
- **Deploy from GitHub (Workers Builds):** build command `npm run build`, deploy command `npx wrangler deploy`. The Worker name must match `name` in `wrangler.jsonc` (`carinova-web`). Node comes from `.nvmrc`. Pushes to `main` go live; other branches get preview URLs.
- **Secrets** are set on the Worker, not in the repo, and survive deploys: `npx wrangler secret put <NAME>` or dashboard → the Worker → Settings → Variables and Secrets → "Secret". Plain-text variables added in the dashboard are removed by the next `wrangler deploy`; use secrets.
- **Logs:** dashboard → the Worker → Logs (kept because of `observability` in `wrangler.jsonc`). A failed sign-up logs its reason there, without customer data.
- **Check Cloudflare behaviour locally:** `npm run preview` (build + `wrangler dev`, http://localhost:8787). It reads `.env`.
- **Domain:** Cloudflare Registrar does not sell `.ni` or `.com.ni`: those are bought from NIC.ni, then the domain is added to Cloudflare and its nameservers changed. A Cloudflare Registrar domain can be moved to another Cloudflare account later (both accounts confirm; only the registration moves, DNS is rebuilt).
- **Connecting a domain:** Worker → Settings → Domains & Routes → Add → Custom Domain, or `"routes": [{ "pattern": "<domain>", "custom_domain": true }]` in `wrangler.jsonc`. Cloudflare creates the DNS record and certificate. A Custom Domain matches one hostname only: for `www`, add a proxied `AAAA www 100::` record and a Redirect Rule from the "Redirect from WWW to root" template.
- **`netlify.toml`** is still in the repo, but Netlify would only serve the static pages: the sign-up API is a Cloudflare Worker.

Comparison that led to D-018:

- **Netlify**: the simplest first deploy (connect the repo, or drag the `dist/` folder onto the dashboard). Free plan is credit-metered: 300 credits/month; 15 per production deploy, 20 per GB, 2 per 10,000 requests. At ~153 KB and 8 requests per first visit, that's about 5 credits per 1,000 home visits, so the free plan covers tens of thousands of visits a month.
- **Cloudflare**: domain, DNS and hosting in one account; requests to static assets are free and unlimited; nearest edge measured at ~35 ms from our connection vs ~90–110 ms for Vercel/Netlify.
- Visitors are in Nicaragua and the US: both providers serve the US well; Cloudflare is closer to Nicaragua.
